Setup

Install the app and connect a local MCP client.

macOS installation

  1. Download the disk image for your Mac: Apple silicon or Intel.
  2. Open the disk image and drag Auto Digger.app into Applications.
  3. Open Auto Digger from Applications.

The preview builds are ad-hoc signed and not notarized. If macOS blocks the official release with an unverified-app or damaged-app message, quit the app and run: 

xattr -dr com.apple.quarantine "/Applications/Auto Digger.app"
open "/Applications/Auto Digger.app"

This removes the download quarantine attribute from that app bundle. Change the path if you installed it elsewhere.

MCP setup

  1. Install Node.js 22 or newer. Your MCP client must be able to run node.
  2. Open Auto Digger and connect your Discogs account for release searches.
  3. Open Settings → AI mix research and choose Enable research access.

Keep Auto Digger open. Access starts disabled after every restart. While enabled, your client can read and edit your crates.

Use the configuration shown in Settings: it contains the correct paths for your installation. The client must run locally on the same computer. This connection has no public server URL.

Claude Desktop

  1. In Auto Digger, select JSON client configuration and copy it.
  2. Open Claude Desktop's claude_desktop_config.json using the path below. Launch Claude Desktop once first if its folder does not exist.
  3. Add the copied auto_digger entry to the existing mcpServers object. Preserve other servers. For an empty file, paste the complete copied JSON.
  4. Fully quit Claude Desktop and reopen it. Look for auto_digger in its local MCP servers or chat tools.
macOS
~/Library/Application Support/Claude/claude_desktop_config.json
Windows
%APPDATA%\Claude\claude_desktop_config.json

Use local MCP configuration, not the remote custom-connector URL field. Current versions list local servers in Settings → Desktop app → Extensions; older layouts use Settings → Developer.

Claude Code

Replace both example paths with the absolute paths shown in Auto Digger's configuration, then run: 

claude mcp add --transport stdio --scope user auto_digger -- node "/path/from/settings/mcp.js" --connection "/path/from/settings/mcp-connection.json"

Open Claude Code and use /mcp to check that auto_digger is connected. Claude Code MCP reference.

Codex

  1. In Auto Digger, select Codex TOML configuration and copy the block.
  2. Add it to ~/.codex/config.toml. Preserve other settings; replace an existing [mcp_servers.auto_digger] block instead of duplicating it.
  3. Restart your Codex client. In desktop MCP settings, the equivalent is a STDIO server named auto_digger, using the displayed command and three arguments.

CLI alternative, with both example paths replaced by the values from Auto Digger:

codex mcp add auto_digger -- node "/path/from/settings/mcp.js" --connection "/path/from/settings/mcp-connection.json"
codex mcp list

Use /mcp to check available tools. Official OpenAI MCP documentation.

Try a request

Start with: Use Auto Digger to list my crates.

For mix research, supply a real mix URL and ask:

Research this mix. Find the original Discogs releases, save them to a Mix picks crate and mark the matching tracks. Keep source links and flag uncertain matches.

Your AI client researches the sources and judges recording matches. Auto Digger verifies Discogs metadata and saves the results. Check the picks and any uncertain matches in Crates.

Troubleshooting

The client cannot find Node
Use command -v node on macOS/Linux or where.exe node on Windows. Put the full Node executable path in the client's command field; leave the arguments unchanged.
The app is closed or access is disabled
Reopen Auto Digger, enable research access and reconnect the client. Disabling access or closing the app revokes the connection.
A file path no longer exists
Copy fresh configuration after moving or updating Auto Digger. Linux AppImage mount paths can change between launches, so refresh the client configuration if needed.
Search fails but crate tools work
Check the Discogs connection in Auto Digger. Keep the token in the app; it is not part of MCP client configuration.
